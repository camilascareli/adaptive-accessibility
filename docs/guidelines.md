# Accessibility Guidelines

## WCAG 2.2

| Topic | Description | Application in Adaptive Accessibility |
|--------|-------------|--------------------------------------|
| Principles (POUR) | Perceivable, Operable, Understandable, and Robust. | Provide the foundation for all accessibility recommendations in the extension. |
| Conformance Levels | A, AA, and AAA. | The project will primarily use Level AA criteria. |
| 1.4.3 Contrast (Minimum) | Ensures adequate contrast between text and background. | Recommend contrast enhancement when low visual comfort is detected. |
| 1.4.4 Resize Text | Content must remain usable when enlarged. | Detect frequent zoom usage and suggest increasing font size. |
| 1.4.12 Text Spacing | Allows customization of spacing between lines, words, and characters. | Recommend increased spacing to improve readability. |
| 2.1.1 Keyboard | All functionality must be accessible through a keyboard. | Detect predominant keyboard navigation and recommend related accessibility features. |
| 2.4.7 Focus Visible | Focused elements must have a clearly visible indicator. | Recommend visual focus enhancement during navigation. |
| 3.3 Input Assistance | Helps users prevent and recover from errors. | Future support for recommendations related to forms. |

## ISO 9241-210

| Topic | Description | Application in Adaptive Accessibility |
|--------|-------------|--------------------------------------|
| User-Centered Design | The user should guide the entire development process. | All recommendations will be centered on user needs. |
| User Participation | Users participate in decision-making processes. | Users will always be able to accept or reject a recommendation. |
| Iterative Process | The system should continuously evolve. | Recommendation rules may be refined throughout the project. |
| User Experience | Considers effectiveness, efficiency, and satisfaction. | Used as a reference to evaluate the quality of recommendations. |

## Nielsen's Usability Heuristics

| Heuristic | Application in Adaptive Accessibility |
|------------|--------------------------------------|
| Visibility of System Status | Explain to users why a recommendation was presented. |
| User Control and Freedom | Allow users to accept, reject, or disable recommendations. |
| Consistency and Standards | Maintain consistent recommendations across different websites. |
| Recognition Rather Than Recall | Use simple and objective language in recommendations. |
| Flexibility and Efficiency of Use | Adapt recommendations according to observed user behavior. |
| Help and Documentation | Clearly explain each recommended accessibility feature. |
