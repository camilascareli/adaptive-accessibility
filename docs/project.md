# Project

## Vision

Adaptive Accessibility aims to make web accessibility more proactive by helping users discover accessibility resources through their interaction patterns rather than relying exclusively on manual browser or operating system settings.

The project combines Requirements Engineering, Software Architecture, Human-Centered Design, and Digital Accessibility to investigate how behavior-driven recommendations can improve the web experience while preserving user autonomy and privacy.

---

## General Objective

Develop a browser extension capable of identifying user interaction patterns and recommending accessibility adaptations based on recognized accessibility standards and usability principles.

---

## Scope

### In Scope

The first version of Adaptive Accessibility includes:

- Browser extension development.
- Interaction event collection.
- Behavior pattern analysis.
- Accessibility recommendation engine.
- Recommendation rules based on WCAG and usability principles.
- User preference management.
- Local data persistence.
- Complete project documentation.

### Out of Scope

The project does not include:

- Medical diagnosis.
- Disability classification.
- Automatic accessibility adaptations without user consent.
- Automatic modification of browser or operating system settings.
- Collection of sensitive personal or health information.
- Replacement of existing assistive technologies.

---

## Target Audience

Adaptive Accessibility is intended for three primary audiences.

### End Users

Users who may experience accessibility barriers during web navigation, regardless of whether they identify themselves as people with disabilities.

Examples include:

- Older adults using digital services.
- Citizens accessing government portals.
- Users who frequently zoom web pages.
- Users who primarily navigate using the keyboard.
- Users who experience reading difficulties due to the visual presentation of web content.
- Users who encounter repetitive interaction problems during navigation.

### Software Professionals

- Software Developers
- Software Architects
- Requirements Engineers
- UX/UI Designers
- Accessibility Specialists

### Researchers and Students

Researchers, educators, and students interested in Requirements Engineering, Software Architecture, Human-Computer Interaction, Usability, and Digital Accessibility.

---

## Personas

To better understand user needs and support the Requirements Engineering process, Adaptive Accessibility will define a set of representative personas based on realistic usage scenarios.

These personas will represent different user profiles, navigation behaviors, accessibility needs, and interaction contexts. They will support the elicitation of requirements, creation of user stories, validation of accessibility recommendations, and evaluation of the proposed solution.

Examples of scenarios to be represented include:

- Older adults accessing government services.
- Citizens using public service portals.
- Users who frequently increase browser zoom.
- Users who primarily navigate using the keyboard.
- Users who experience reading difficulties caused by interface design.
- Users interacting with educational, financial, healthcare, and e-commerce websites.

Each persona will describe the user's background, goals, behaviors, challenges, accessibility needs, and interaction patterns relevant to the project.
